# Phase 36C / FR09: signed server-session concurrency evidence gate (source only)
- Batch/ledger: Phase 36C / FR08 prerequisite / FR09; P36-0087; 2026-10-26.
- Problem: 5000 distinct user JWTs with 225000 paced HTTP200 reads in 15 minutes did not prove 5000 authenticated sessions concurrently active throughout the 15-minute window.
- Root cause: the existing mixed-capacity verifier accepted a client-written single aggregate authenticated_active_users_min and unique count. The test fixture could claim completion without a server-side sampled concurrency series.
- Scope: standard-library-only FR09 evidence gate and unit tests; no runtime worker, production, database, credentials, user records, network, external providers, migration, or package upgrade.
- Corrected evidence contract: at least 31 strictly increasing server-side samples covering a 900-second measured steady window; gaps at most 30 seconds, first and last samples bound to exact windows, >=5000 authenticated simultaneous sessions and distinct active users at every sample. User count cannot exceed concurrent sessions or aggregate unique users. All integer and timestamp fields must have valid finite types and bounds.
- Provenance control: source server-authenticated-session-tracker-v1; server concurrency series, start/end timestamps and source are integrity-bound to a SHA256-HMAC value. The verifier requires a separately trusted operator-owned 0600 HMAC key file, owner EUID, regular file and minimum 32-byte key. Wrong key, missing key, altered count, altered time, client-origin telemetry or invalid key-file permissions FAIL CLOSED. No key was created, enrolled, exposed or provided by the user.
- Important limitation: matching a trusted key verifies the signer, not that its underlying sessions are physically genuine. Authentic backend session instrumentation and independently audited recorder provenance and synchronized clocks must be implemented and verified separately before real acceptance. This test uses a clearly labeled TEST-ONLY fixed key, never a production key.
- Regression: 71 strict verifier tests passed and 140 combined pure FR09 profile/gate/reads/local inference tests passed. Reporting-governance tests are tracked separately in CI. Explicit negatives cover self-claimed 5000 users, insufficient minimum, missing samples, 30-second gaps, malformed values, unsigned and rewritten logs, wrong key, unsafe key permissions, and read-only evidence substitution.
- Genuine FR09 preflight: official origin/main preflight against verified independent LUKS lab observed ~67.3 GiB free (min 40 GiB), zero lab containers, and exited code 2 solely because FR08 full independent admission remains unaccepted. Evidence: /var/lib/aionex-migration/fr09-isolated-safe-preflight-20261026/PREFLIGHT-20261026.json (SHA256 60ff4ecdbffc86e798cb8f3638b9f8e5a527f61b15770d8397d9b5b22391bf35). Heavy load was NOT authorized or started.
- Release and rollback: source-only change on isolated worktree; no deployment or restart. Requires protected GitHub CI before merging. Revert amended source as fallback. Previous paced read results are baseline, not FR08/FR09 acceptance or 5000 truly simultaneous user acceptance. No 15000 model-backed durable completions or 72h natural acceptance are proven.
- Final decision: HOLD. Remaining real Owner FR08, authenticated server-capture trust, full 5000/15000 mixed AI workload, provider quota/budget, and 72h FR25 stability.
