# Phase 36C / FR08: surface failed-starting provider state alongside Owner review

- Ledger: P36-0088. Date: 2026-10-26. Source-only Owner operational product improvement.
- Production symptom: read-only PostgreSQL showed 7 Identity Media executions in needs_review/not_started, alongside 2 failed/starting executions, 4 failed/not_started and 4 completed/succeeded. An additional lease/secondary-provider ref was present in the aggregate. No user or provider credentials were read, printed or changed.
- Existing supported Owner route and UI: /owner/identity-media/executions/recovery-review and IdentityMediaRecoveryReview.tsx already display the 7 needs_review records without provider/job secrets, but do not show failed local executions still marked starting/processing by an external provider. Local status failed does not establish remote cancellation, cost, refund or terminal state.
- Root cause: the original triage query restricted status strictly to needs_review, and prior tests only asserted that review cohort. The Owner UI could therefore omit unresolved provider-start states while displaying a misleading no-pending-review message for a tenant with only failed-starting work.
- Change: reuse the existing Super Owner protected GET route; add two independent bounded SELECT count queries and one bounded projected SELECT for status=failed and provider_state in starting/processing. Preserve all previous response fields, and append failed_provider_state_unverified, missing/reference counts, bounded records and truncation. Source-only API continues to require require_super_owner and intentionally provides no retry, approval, cancel or provider GET endpoint.
- Security / privacy: only execution id, operation, provider, state, attempts, known safe static error categories, reference-present boolean and created time are returned. No provider job ID, prompt, input media, subject identity, customer storage path, token, invoice or raw error messages are returned. Missing provider ref is never treated as evidence of no external bill. Both status cohorts have automatic_replay_allowed=false and actual_provider_charge_verified=false.
- UI: read-only separate section for terminal-local failures with remote status uncertain, safe human next-step language; no active buttons or approval controls added. Distinct counters remain separate and do not count failed rows as needs_review.
- Isolated verification: 18/18 targeted native unittest cases passed in a network-disconnected read-only official backend container using the updated source mount. Tests cover redaction, query SELECT-only semantics, count consistency, limits, source authentication route, seven current-style reviews plus two failed rows, invalid states and failed-only statuses. TypeScript tsc --noEmit --incremental false passed; Prettier formatted the affected UI file. Full protected CI remains required.
- No schema/migration/new dependencies/provider purchase, no production deploy/restart, no customer row mutation, no manual retry or release acceptance. No FR25 observer generation change.
- Rollback: revert only this Owner route projection and UI. The existing needs_review read-only behavior is preserved.
- Remaining full launch gates: independent FR08 authentic Owner/customer recovery and rights, original remote provider-history and billing reconciliation of ambiguous historical operations, FR09 5000/15000 full real mixed acceptance, quotas/costs, and 72 hours natural FR25.
- Verdict: SOURCE_READY_FOR_CI, not FR08_COMPLETE, not RELEASED_VERIFIED.
