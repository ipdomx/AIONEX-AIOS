# Phase 36C / FR09 — AI integration completion is not full governed approval

- **Receipt ID:** P36-R-36C-FR09-20261025-RELEASE-TRUTHFULNESS
- **Batch:** Phase 36C / FR-09 / FR-25
- **UTC source evidence:** 2026-10-25 21:00–22:00Z; exact test details are retained in the receipts below.
- **Objective:** Prevent an AI-only model-routing cycle from falsely announcing full Owner, human, engineering, workforce and final-release approval.
- **Production gap before change:** `DeterministicProjectAIIntegrationRunner._run_async()` could return `approved=True`, `readiness_score=1.0` **and simultaneously** `integration_foundation=True`, `all_governance_layers_executed=False`. `ProjectExecutionWorker.complete()` persisted the approval flag, moved the project to the active/approved state and issued an overclaiming completion notification. The proof of generated model text is not equivalent to full governed project acceptance.

- **Material problem and root cause (P36-0086):** The integration component correctly marked `all_governance_layers_executed=False` but also returned optimistic approval/readiness fields; the durable worker treated those optimistic fields as final. Earlier provider-routing tests verified route selection and work completion but did not assert the conflict between partial integration and whole-project approval.
- **Notification and audit truthfulness:** Incomplete AI-only integration now sends \`Project AI work completed; final approval withheld\` and explicitly says Owner/security/workforce/release governance was not executed. It does not tell the user a full governed cycle occurred. The existing fully governed legacy notification stays unchanged. The 100 synthetic project/worker acceptance test verifies **all 100 resulting notifications** have this correct title, text and \`release_approval_withheld\` payload.\n- **Fix and regression prevention:** Change the integration runner to return false approval and zero readiness. At the worker completion boundary, a second fail-closed guard **only for** `integration_foundation is True` with `all_governance_layers_executed is not True` sanitizes the persisted approval/readiness and adds a fixed withheld-approval reason, without mutating the caller's result object. Fully governed legacy results remain unchanged.
