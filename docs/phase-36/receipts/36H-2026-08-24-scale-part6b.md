## Scope

## Attempt 1 — real defect found

The first runtime attempt migrated the disposable database to Alembic `20260824_0041` and reached the Redis stage, then failed because `RedisRealtimeBackplane.start()` created its listener before any channel had been subscribed. redis-py rejected `get_message()` without a Pub/Sub subscription, the listener terminated, and the old listener-derived `started` property became false before `subscribe()`.

The fix changes the backplane lifecycle itself: `start()` now establishes the Pub/Sub object but does not start the listener; the first successful subscription starts the listener; removing the last subscription cancels the listener; the backplane lifecycle has an explicit started state independent of whether a tenant currently has a local socket. A regression test verifies that no listener read occurs before the first subscription and that the listener stops after the last unsubscribe.

Before Attempt 2, cleanup was verified at zero test organizations/users/rooms/participants/grants.
