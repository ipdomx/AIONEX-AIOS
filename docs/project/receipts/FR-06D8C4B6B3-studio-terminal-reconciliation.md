# FR-06D8C4B6B3 — Studio terminal crash reconciliation

Source-only, database-only terminal reconciliation after B6B1 terminal-candidate export and B6B2 read-only host quarantine revalidation. This stage does not touch Studio filesystem bytes, delete quarantine/final names, retry work, claim normal-success settlement, control containers/processes, open/close admission, deploy Production, or migrate Production.

The stage adds immutable ledger `studio_crash_reconciliations` at migration `20260920_0062`. A new reconciliation requires the exact B6B1 terminal candidate and exact B6B2 host receipt, revalidates the retained B6A containment plus raw execution/publication/crash evidence, rejects any conflicting normal-success/prestart/poststart terminal receipt, and requires the current closed Studio maintenance authority to match the authority embedded in B6B1 exactly.

A valid record represents terminal state `crash_reconciled_quarantine_retained`. It may set `terminalization_authorized=true` and `blocker_cleared=true` only for the exact execution and crash-observation pair proven by the chain. The retained quarantine remains evidence. `retry_authorized=false`, `filesystem_cleanup_claimed=false`, `cleanup_authorized=false`, `settlement_authorized=false`, `quarantine_deletion_permitted=false`, `final_deletion_permitted=false`, `process_drain_verified=false`, and `full_host_closure=false` remain fixed.

Exact replay of an already-recorded reconciliation is idempotent even after a later maintenance-authority rollover, because it does not create new terminal authority. A first record after authority drift fails closed and requires a fresh B6B1/B6B2 chain. Different evidence cannot replace an existing immutable reconciliation.

Registry integration subtracts exactly two blockers for one valid reconciliation: the unresolved execution blocker and the matching crash-observation reconciliation blocker. Invalid/orphan/drifted reconciliation evidence subtracts nothing and adds an invalid-reconciliation blocker. Raw containment/crash evidence remains visible and is annotated terminally reconciled rather than deleted.

Migration `0062` has no backfill. A fresh disposable PostgreSQL database upgraded through head `20260920_0062`, a second `upgrade head` was idempotent, and downgrade to `0061` failed closed because terminal evidence may not be discarded.
