## Acceptance and boundaries

- 44 new source-lock, file-integrity, fixture-selection and build contracts pass.
  Full Root-suite counts and exact source hashes are retained in runtime evidence.
- 2,390 upstream test/subtest events pass, with zero failed/skipped events within
  the selected eight-package scope: versions, match, CPE, v6 database, Python,
  JavaScript and dpkg matchers, and JSON presenter. This is not the complete
  upstream suite, a race run, or external registry/daemon integration acceptance.
  Repeated runs repeat this scope and must not be summed as distinct coverage.
- The initial selected run had 32 failures because the isolated lab lacked Git,
  needed by the upstream fixture-source fingerprint. A public Debian Git package
  was supplied read-only, and an empty private repository was initialized only in
  the extracted test source. No upstream assertion was changed or skipped, and
  no production Git repository or daemon socket was exposed to the tests.
- Native image acceptance used the real application argument builder, execution
  adapter and finding normalizer. A database generated by the upstream tests
  contains one fixture advisory; synthetic Django metadata at 1.2.5 matches it,
  while 1.3.5 does not. The failure-severity threshold returns 2 for the affected
  fixture and 0 for the fixed fixture. This is an explicitly isolated historical
  test database, NOT an update or validation of the current public feed.
- The actual CLI and DB reader reject a changed database checksum, a missing
  database and malformed SBOM input. Empty input returns no matches. Hash and
  age verification stay enabled. Neither fixture database nor package metadata
  changes during the accepted scans. Fixture data is never installed in the
  production image as a runtime vulnerability feed.
- All functional tests ran in a disposable unprivileged network-disabled
  container. No client project, live credential, provider or production DB was
  used. Downloading public source/compiler/module inputs is a separate phase.
- The first local image recipe used a BuildKit-only COPY option; the legacy
  builder rejected it. The corrected recipe sets the staged binary's executable
  mode before ordinary COPY. The first functional assertion expected a wrong
  JSON source field; it was corrected to the upstream type/target contract.
  Failures remain recorded; application behavior and guards were not changed.
- Ruff and Mypy pass for both source scripts. The initial type-check runner was
  missing the actual application source path; the final runner resolves it.
