# FR-06C5D guarded host-state cutover

This source prepares an initial migration of host/operator state and application secrets into the accepted encrypted host-state vault. It does not execute a production cutover on merge. C5C1 bootstrap, the canonical MCP2 installation, vault provisioning, external key custody and recovery/header proof must be accepted first.

Planning and execution share one operation lock. The executor rechecks source, evidence, topology and resource identities under that lock, durably consumes the plan before copying, and rechecks the maintenance authority after precopy before stopping any watcher or application. Every mutation has a durable intent. A candidate-start attempt permanently blocks automatic reuse of the initial-cutover path, even if its binds later disappear. Incomplete or unreadable journals require reconciliation.

Legacy seals, gate files and the enable link have recorded identities. Completed seal options are rechecked even below a candidate bind. The enable link is published without replacing an existing destination after its inode identity is captured in a private staging directory. Rollback checks all affected resources before changing them, removes only proven owned resources, and verifies legacy identities before restarting Docker. It restores every original restart policy, including retry limits, and reports restoration only after bounded health checks confirm the exact container identities and service membership. Candidate acceptance repeats identity and encrypted-bind checks after HTTP and tunnel stabilization.

The underlay gate inspects visible process/thread file descriptors, cwd, root and mapped-file references. The metadata inventory requires ordinary files/directories, rejects symlinks and special files, and matches device/inode identity as well as source paths, including references through external aliases. Source identities are inventoried again after the proc scan. Unattributable unlinked references on a legacy filesystem conservatively block. Permission or I/O failures block the migration; a vanished reference is ignored only when its disappearance is verified. This observational scan is not an atomic guarantee about all possible kernel-held references. The final-copy manifest verifies paths, types, mode, ownership, sizes and content hashes; rsync copies extended metadata using `-aHAX --numeric-ids`.

Behavior tests use temporary files, a mount-table model, Docker fakes and synthetic proc trees under `nobody`. They do not substitute for the guarded operational acceptance. No live vault, bind, systemd, Docker, swap or `/tmp` action is performed by the test suite or source merge. FR-06 remains in progress.
