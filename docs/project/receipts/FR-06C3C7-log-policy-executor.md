# FR-06C3C7 — guarded volatile-log activation

This source-only executor activates the already-reviewed C3C6 log boundary later in C3E. It is intentionally separate from Redis cutover: Redis can be recovered without changing host logging, and logging can be rolled back without copying or mutating Redis AOF.

The apply path requires a retained C3E Redis closeout plus an operations-vault host-ready check and fresh protected-main evidence. A live file-descriptor inventory must contain only the known logging processes: journald, rsyslog, fail2ban and unattended-upgrades. Any unknown direct `/var/log` holder fails closed. The executor stops rsyslog, fail2ban and unattended-upgrades, installs only repository-pinned systemd sources, mounts `/var/log` on tmpfs, restarts journald into `Storage=volatile`, recreates standard log directories, then proves no process still holds a file descriptor on the hidden plaintext underlay device before restarting the three managed services. Final acceptance repeats the hidden-underlay FD check and verifies the live filesystem and service state.

Rollback stops all managed direct log services before unmounting tmpfs, removes only files whose SHA-256 still matches the executor-installed repository sources, restarts journald on the legacy path and then restores rsyslog, fail2ban and unattended-upgrades. It never deletes the old root-filesystem log underlay and never claims secure erase of historical blocks. FR-06 protects future active selected storage domains; full-disk historical remanence remains outside that claim.

- Live rollback evidence showed `syslog.socket` can socket-activate `rsyslog.service` after a normal stop; activation now quiesces that socket explicitly before rsyslog and restores the socket before rsyslog on the volatile mount.
