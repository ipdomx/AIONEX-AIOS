# FR-01 — المرجع الموحد وإصلاح MCP2

الحالة عند مراجعة المصدر: مرشح مختبر محليًا، لا يثبت هذا الملف تثبيتًا حيًا قبل الدمج. حالة النشر النهائية في runtime/events.jsonl والتقرير المولد.

## الأسباب التي أصلحت
1. PROJECT_ROOT وسبعة افتراضيات عامة تشير إلى worktree محذوف.
2. wrapper يختار مصدرًا من أحدث ملف backup متغير عند الإقلاع.
3. أمر restart قد يوقف كل tunnel-client، وليس MCP2 فقط.
4. معالجة TimeoutExpired قد تستقبل bytes وتفشل قبل تنقيح المخرجات.
5. أوامر RunPod التاريخية حملت aliases خفية تنشئ/تعدل موارد بدل معنى اسم الأداة.

## التغيير
مصدر مستقل متعقب في ops/mcp2/server.py يحفظ الأدوات الـ28 وعقودها. الافتراض /opt/AIOS والمسارات النسبية مثبتة؛ server_status يعلن النسخة ومرجع التقرير. إعادة الاتصال تستهدف aionex-phase22c-2-tunnel.service فقط؛ لم تستعمل aliases الخفية أو تشغل موارد RunPod.

مثبت ذري ذو تطابق SHA/commit ومقارنة الحالة القديمة ونسخة رجوع، لا ينفذ restart تلقائيًا. اختبارات العقد لا تستدعي مزودًا ولا تستخدم قاعدة إنتاج.

PLAN يحتوي 26 دفعة رئيسية، 62 قدرة، 18 finding، 16 مجموعة وظائف سابقة، و18 PR تبعيات. سجل ذو قفل وإيصالات idempotent وتوليد ذري يمنع اعتبار الدمج نشرًا أو اختبار تحكم قديم شهادة للألف متعدد المشاريع.

## قبول/أمان/رجوع
اختبارات MCP2 الأولية 19/19 PASS. العدد المجمع يحفظ بإيصال التنفيذ بعد تشغيل اختبارات المرجع. يلزم جميع الفحوص المحمية ثم الدمج، تطابق المصدر الحي، server_status ومسار عمل افتراضي بلا cwd، وثبات خدمات المنصة والأنفاق الأخرى. لا تغيير Cloudflare/DNS، لا مفتاح أو محتوى مستخدم في الأدلة، لا توليد مدفوع، لا ترقية dependency ضمن هذا الإصلاح.

الرجوع: إعادة ملف MCP2 السابق ذي البصمة المسجلة، ثم خدمة MCP2 وحدها إن لزم؛ لا pkill عام ولا rollback لتطبيق PR603. لا تعاد عملية بنتيجة غير معلومة دون قراءة الحالة.

## اكتشاف أثناء الفحص الموسع
أداة run_pytest القديمة تستدعي executable مباشرة؛ عند worktree غابت scripts وpackages عن sys.path، وفشل جمع اختبارين قبل التنفيذ. أصلح المصدر الاستدعاء إلى Python -m pytest وأضيف اختبار منع رجوع. لا يحتسب التشغيل الأول نجاحًا؛ يسجل العدد النهائي بإعادة تشغيل كاملة.

التحقق المحلي النهائي قبل PR: **897/897 Core PASS**، بينها **34 اختبارًا جديدًا** (20 MCP + 14 مرجع)، وفحص FastMCP 3.4.5 الحقيقي يطابق 28 أداة وسبعة افتراضيات /opt/AIOS. صحح فاحص إطار العمل استخدام list_tools بدل get_tools القديم؛ هذا تصحيح غلاف الفحص وليس عطلًا في أدوات المرشح. يعاد تدقيق الملفات الجديدة بعد إدراجها في Git.

## قيد GitHub ظهر عند النشر
رفض GitHub رفع تعديل workflow لأن OAuth الحالي لا يحمل workflow scope. لم تغير صلاحية الموصل ولم تتجاوز الحماية؛ أزيل تعديل YAML غير الضروري. اختبارات المرجع الـ14 تعمل ضمن فحص Core المحمي الموجود الذي يشغل كل tests؛ لذلك يبقى إنفاذ الخطة واكتشاف ضعف معايير الإغلاق في CI دون تعديل سير العمل. المحاولة المرفوضة لم تنشر الفرع.
