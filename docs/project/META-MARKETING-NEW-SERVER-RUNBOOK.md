# Meta Marketing original credentials: NEW host opt-in backend integration

**Status 2026-10-11:** The existing AIONEX AIOS backend image includes Meta Marketing owned-assets and sandbox read-only connectors, controlled-pilot verification, target discovery and separately guarded non-spend write adapters.

The original OLD Meta owned API credential (195 bytes) and sandbox credential (204 bytes) were transferred over a **one-use SSH key** whose scope was restricted to the OLD host's IP address and a forced import command accepting **exactly two token files**. The credentials were placed in the NEW encrypted host-state vault with owner root and mode 0600, and their size/SHA256 were independently compared between hosts. After confirmation, the temporary NEW SSH authorization was revoked without altering existing authorized keys; the temporary OLD SSH identity was destroyed. No raw token was printed or published.

Isolated offline tests in an application-image container verified the original Meta connector source loads both files under the allowlisted read-only secrets directory without network. Separate sandbox/owned **GET-only** Graph API requests from NEW then passed: owned authorized ad-account discovery reported 2 accounts, and the sandbox ad account returned status active. No advertising operations, writes, campaigns or charges were made.

**Live backend integration pending reviewed rollout:** The currently running production backend does not mount the two Meta credentials and has no Meta credential-path environment variables. To make live authenticated owner-pilot routes able to invoke Meta, the opt-in overlay `web-dashboard/docker-compose.meta-operator-secrets.json` adds two **read-only file binds** to the **backend only**, with `create_host_path=false` and required external environment-variable sources. It does not embed or enable tokens, ad-account IDs, write permissions or spend.

Store any necessary runtime environment in a root-private location, never Git.
3. Specify the existing exact Compose input list from the container's `com.docker.compose.project.config_files` labels (production + FR06 encrypted asset/database/backup/operations overlays + pinned-image override), then append the optional Meta JSON overlay **last**. Provide `AIOS_META_OWNED_TOKEN_HOST_FILE`, `AIOS_META_SANDBOX_TOKEN_HOST_FILE` and `AIOS_META_SANDBOX_AD_ACCOUNT_ID` through approved private operator environment, not repository defaults.
4. Run `docker compose ... config --format json` into a protected root-only output file, inspect only **sanitized names/mode/volume diffs**, verify existing production image, networks, volumes, healthcheck, app permissions and all non-Meta environment remain identical. Never print the full config since it includes production secrets.
5. Only after a reviewed admission window, backup/rollback readiness and owner acceptance, recreate **backend only** with `--no-deps`; never `docker compose down`, remove volumes, rebuild PostgreSQL, or silently change real-spend permissions. Verify backend ready/auth boundaries/owner routes/Meta GET-only and no provider-spend attempts; revert using the original exact Compose file list on any regression.

The overlay is **optional**, not yet in the deployed Compose input list, so *migration of original credentials and successful live read-only provider probes are proven, but live UI pilot usage is NOT yet certified*.
